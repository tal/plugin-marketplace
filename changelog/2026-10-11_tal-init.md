# tal: `/tal:init` points a project's AGENTS.md at its tal commands

Most tal skills are now explicit-only, so an agent working in a project can't
see them. `/tal:init` detects which ones fit the project and writes a short
request → command table into its `AGENTS.md`. The context cost lands only in
projects where the skills apply.

## Added

- **`skills/init/`** (explicit-only: `disable-model-invocation: true` plus
  `agents/openai.yaml`). `/tal:init` in Claude Code, `$init` in Codex.
  - **Detect:** `scripts/detect.sh` prints read-only `key=value` signals:
    Xcode projects, `fly.toml`, deploy-ish push workflows, GitHub and PaaS
    remotes, `.config/deploy.yml` targets and pipelines (through deploy's
    `check-config.sh`), the state of `AGENTS.md` / `CLAUDE.md`, the managed
    block, and existing project skills.
  - **Catalog:** `deploy` (configured, or `/deploy config init` when a
    deploy signal exists without a config), `appstore-connect` (Xcode),
    `pr-thread-reply` and `/tal:pr:address-feedback` (GitHub remote).
    Auto-triggering and project-agnostic skills never get a row.
  - **Write:** asks which skills to include, then writes rows in the project's
    own names (e.g. `/deploy testflight external`) between
    `<!-- tal:init:start -->` / `<!-- tal:init:end -->` markers. Creates
    `AGENTS.md` if missing and adds `@AGENTS.md` to `CLAUDE.md` so Claude Code
    reads it. Shows the change and asks first. Re-runs replace only the block.
    `/tal:init remove` deletes it. It offers a commit of just those files, and
    warns if they already had uncommitted changes.
- **tal `AGENTS.md`:** `/tal:init` is now the suggested way to get help with
  explicit-only skills in the projects that need them, replacing per-repo
  pointer skills. New project-scoped explicit-only skills need a catalog row.

## Verified

- `detect.sh` under `/bin/bash` 3.2:
  - weather-range: `xcode`, `github_remote`, `deploy_target=testflight internal
    external`, `claude_md=imports-agents`, and its existing `testflight` pointer
    skill.
  - sports-range-coach: `fly_toml` and its CI workflow as `deploy_workflow`.
  - Fixtures: a present, missing and one-marker (`broken`) block, a dokku
    remote, a `pull_request`-only workflow (correctly skipped), an invalid
    `deploy.yml`, and a non-git folder.
- The parent `~/Projects` folder lists many Xcode projects across
  subfolders, so the skill refuses a folder of projects. `.playground`
  workspaces are skipped.
- The skill itself hasn't been run end to end in a project yet.
