# The fixture library — every manifest and what it proves

`fixtures/library/` is the **only** test surface for the server (the real library is off-limits to agents in
that repo). It is generated by `bun scripts/make-fixtures.ts` — idempotent, existing files are kept (edit the
generator, delete the file, regenerate). To cover a new manifest case, add it to the generator; never reach
for the real library. On-disk contents verified 2026-08-30.

Fixture passwords (test data, listed openly in the server README): `garden-hose-42`, `second-key-77`,
`contract-key-9`, `album-key-5`.

Tests that pin manifest behaviour (grep these first when something changes): `test/scan.test.ts`
(classification, inheritance, narrow-not-widen, invalid → hidden, root manifests, gallery rule),
`test/access.test.ts` (guard decisions, no existence oracle, unlisted filtering, bypass),
`test/server.test.ts` (HTTP shapes: 303/401/404/429, unlock flow, headers, apps),
`test/secrets.test.ts` (no password anywhere serialised), `test/folder-preview.test.ts` (picture rule),
`test/apps.test.ts` (build trust), `test/clean-routes.test.ts`, `test/ambiguity.test.ts`.
