# `.library.yml` — folder manifests for the AI Library server

The AI Library server (`~/Projects/ai-library-server`, Bun + Hono, deployed at `https://library.tal.by`)
renders a folder tree as a browsable library. Its **only** per-folder configuration is an optional
`.library.yml`. This skill is a source-verified summary of what that file can do and how it fails.

Source of truth, in this order: `schema/library.schema.json` → `src/scan/manifest.ts` (load, validate,
inherit) → `src/scan/catalog.ts` (resolution, previews, apps) → `src/access/guard.ts` (enforcement).
Verified against commit `ffef3bc` (2026-08-30); line numbers in the reference files are from that commit —
grep by symbol name if they drift. When this skill and the source disagree, the source wins.

## Workflow

1. Identify the exact folder and **which copy** it lives on: the Mac (`~/Downloads/AI Library`) or the NAS
   copy the server reads (`/mnt/synfeld-backups/AI Library` on bee1). They are synced by Tal, not by agents.
2. Read every ancestor's `.library.yml` first — `visibility` and `listing` inherit and can only narrow, so
   the parent decides what the child can still do.
3. Pick a shape from *Recipes* / `examples/`, draft it with the `$schema` line first, quote anything
   numeric or containing ` #` / `: `.
4. Validate the draft (see *Validate a draft*) and state the effect — including any widening warning it
   will produce and that a **rescan** is needed before the server notices.
5. Hand the YAML to Tal unless he asked you to write this exact folder's manifest in this conversation.

## Rules of engagement — who writes manifests, and where

From the server repo's `AGENTS.md` and Tal's standing decisions. Not optional.

- **The real library (`~/Downloads/AI Library`) is Tal's.** Manifests there are placed **by Tal, by hand,
  when he decides**. Default posture: draft the YAML, name the folder, explain the behaviour — and let Tal
  place it. Write a `.library.yml` into the real library only when Tal explicitly asks for that specific
  folder in the current conversation; never sweep manifests across many folders on your own initiative.
- **Inside `~/Projects/ai-library-server`:** never read, scan, stat, test against, or reference the real
  library. All testing uses `fixtures/library/`, generated by `bun scripts/make-fixtures.ts`; a missing
  case is added to the generator. Fixture manifests are test data and fine to edit through the generator.
- **`Travel/2026-07-23_sweden-norway-trip/` is hands-off.** No manifest, no planning, no special-casing.
- **Never run `ai-library-mirror.sh` from an agent session.** A manifest written on the Mac reaches the
  server only after Tal syncs; one written directly on the NAS is wiped by a future full mirror from the
  Mac. Say which of the two Tal is choosing.
- **Passwords are plaintext and travel** (synfeld, rclone to Google Drive, every grep and every agent that
  reads the tree). Throwaway, unique per folder, never a password that protects anything real. Don't repeat
  a real manifest's password into logs, changelogs, commit messages or summaries.
- **The server has no write path into the library and never gets one.** No admin UI, endpoint, or script
  may modify library content — don't propose one.
- **After a manifest lands on the copy the server reads, rescan:**
  `curl -X POST -H "Authorization: Bearer $ADMIN_PASSWORD" https://library.tal.by/_/rescan`, or the
  **Rescan now** button on `/_/unlisted`. Both 404 unless `ADMIN_PASSWORD` is set.

## Ten facts about the file

1. **Name:** exactly `.library.yml`, inside the folder it describes — any folder, including the library
   root. `.library.yaml` is silently ignored. Key names and enum values are **case-sensitive**
   (`Visibility:` is an unknown key, `Protected` an invalid value).
2. **Optional, every key optional.** An empty or comment-only file is valid and declares nothing — but its
   *existence* still changes structure (see *gallery rule*).
3. **Validated** with Ajv (draft-07) against the JSON Schema the server serves at
   `GET /_/schema/library.json`, plus a code re-check of the same rules. `additionalProperties: false` at
   the top level and inside `app`. Unknown key → whole manifest invalid.
4. **Editor line** (put it first): `# yaml-language-server: $schema=https://library.tal.by/_/schema/library.json`
   (dev: `http://localhost:8420/_/schema/library.json`). Trap: the schema's own `$id` lacks `/_/` and 404s.
5. **YAML 1.2 core schema**, strict, unique keys: bare numbers are numbers and `null`/`~` is null, so
   `title: 2026` or `password: 12345678` fail `type: string` and **hide the folder**. Quote anything
   numeric. In a plain scalar ` #` starts a comment (`password: pw #x` → `pw`). Duplicate keys and a second
   `---` document are parse errors. `yes`/`no` are strings (fine).
6. **Fail closed.** Any invalid manifest → that folder *and everything under it* is treated as `hidden`:
   never catalogued, answers 404 (or its locked ancestor's answer). An `error`-level warning names the
   folder and the offending key/keyword — never the value.
7. **Read only at scan time:** boot and `POST /_/rescan`. No file watcher. Edits always take effect on the
   next rescan.
8. **It is a dotfile**, so it is never an item, never searchable, never servable by any URL — including
   inside app folders and via `/_/api/files`.
9. **The server never writes it.** Every write goes to `CACHE_DIR`; the container binds the library `:ro`.
10. **Passwords are plaintext in the file** — see *Rules of engagement*. The server never serializes,
    logs, or returns them.

## Keys at a glance

| Key | Values | When absent | Inherits? (narrow-only = a child may tighten, never widen) | What it does |
|---|---|---|---|---|
| `kind` | `collection` \| `app` | `collection` | no | `app`: the folder ships a static app; nothing under it is indexed; **requires** an `app:` block (and `app:` requires `kind: app`) |
| `visibility` | `public` \| `protected` \| `hidden` | inherited; root `public` | **yes, narrow-only** | `protected`: unlock prompt for the whole subtree, **requires** `password`; `hidden`: never scanned, 404 |
| `password` | non-empty string | — | no | required iff `visibility: protected`; **only** allowed then; compared exactly (no trim) |
| `listing` | `listed` \| `unlisted` | inherited; root `listed` | **yes, narrow-only** | `unlisted`: link-only — absent from parent grid, home, `/_/api/tree`, global search; `noindex` headers on every route under it |
| `title` | non-empty string (trimmed) | intro frontmatter `title` → intro's first non-generic `# H1` → prettified dirname | no | display title everywhere: card, page `<h1>`, crumbs, `<title>`, unlock heading, API, `/_/unlisted` |
| `preview` | folder-relative path, or `none` | the folder's macOS custom icon if it has one, else the 📁 glyph | no | card picture: image/video/PDF inside this folder; `none` forces the glyph |
| `app.entry` | folder-relative path | — | no | required with `kind: app`; that HTML is served at the folder's URL with `window.LIBRARY` + `<base href>` injected |
| `app.build` | folder-relative path | no bundle | no | `Bun.build` entry — **only** honoured when the folder path is in the server's `TRUSTED_APPS`; otherwise ignored with a warning |

Relative-path rules (`preview`, `app.entry`, `app.build`): no leading `/`, no empty / `.` / `..` segments;
backslashes are normalised to `/`. `preview` additionally rejects any segment starting with `.`. A
**malformed** path invalidates the manifest (folder hidden); a well-formed path that points at nothing only
warns. Full per-key detail and error strings: `references/keys.md`.

## Two axes: `visibility` × `listing`

`visibility` = who may **open** it. `listing` = who may **find** it. Independent, both inherited from the
nearest ancestor that sets them, both **narrow-only**: `public → protected → hidden`, `listed → unlisted`.

| `visibility` | `listing` | Behaviour |
|---|---|---|
| `public` | `listed` | default — anyone, appears everywhere |
| `public` | `unlisted` | **link-only** — works for anyone holding the exact URL; absent from every index and from global search |
| `protected` | `listed` | listed with a lock badge; opening anything under it prompts for the password |
| `protected` | `unlisted` | **link-only *and* password-gated** — "here is the link, the password is X" |
| `hidden` | *(ignored)* | never scanned; implies unlisted; a `listing:` beside it is silently ignored |

Rules that follow from `resolveAccess` in `src/scan/manifest.ts`:

- **Widening is ignored, not fatal.** A child that declares a *wider* value keeps the inherited one; a
  `warn`-level warning is recorded — `"<path>: visibility 'public' would widen inherited 'protected' — ignored"`
  (same shape for `listing`) — and every other key in that file still applies. The warning is logged
  **and rendered publicly** in a `<details>` block on the folder's page.
- **No escape hatch.** You cannot make a public sub-folder of a protected folder, nor relist a sub-folder
  of an unlisted one. A descendant of an unlisted folder is unlisted, full stop.
- **Re-keying:** `protected` under `protected` is legal (equal rank). The child becomes a second guard:
  the **parent's** password opens everything below it including the child; the **child's** password
  opens only the child's subtree. The unlock prompt asks for the **nearest** guard. The child key never
  opens the parent.
- **Only a folder that itself declared `protected` is a guard.** `/_/unlock?folder=Invoices/2026` for a
  merely-inherited folder is a 404, exactly like an invented name.
- **`hidden` stops the walk.** Nothing below a hidden folder is read, so a child cannot un-hide itself.
- **Root manifest works.** `visibility: protected` at the root puts the whole library behind one password
  (`/` → `/_/unlock?folder=&next=%2F`); `visibility: hidden` at the root yields an empty library plus an
  `error` warning; `listing: unlisted` at the root unlists everything.

## Access behaviour cheat sheet

| Folder declares | Visitor without the password | Parent grid / home / `/_/api/tree` | Global search |
|---|---|---|---|
| *(nothing)* | content | yes | yes |
| `visibility: protected` | pages **303** → `/_/unlock?folder=<guard>&next=…`; `/_/file/*`, `/_/thumb/*`, `/_/api/*` → **401** `{error:'locked',guard}` — for every path under it, real or invented | the **folder** is listed with a lock; its items and sub-folders are absent until unlocked | absent until unlocked (a sub-folder unlocked with its own key contributes) |
| `visibility: hidden` | **404** ("Nothing at this address.") — or the locked ancestor's answer | never scanned | never |
| `listing: unlisted` | content (or the prompt if also protected), with noindex/no-referrer headers on every route under it (details in the reference) | absent, always — except inside the unlisted folder's own page | absent; a search scoped to it (`?in=<folder>`) finds its content |
| invalid `.library.yml` | 404 (or the locked ancestor's answer) | never scanned + loud `error` warning | never |

- **Unlock:** `POST /_/unlock` → signed `lib_session` cookie holding `{folder → expiry}`, never a password.
  One unlock covers the guard folder **and everything under it**, sub-folders with their own key included;
  unlocking a child never unlocks the parent. TTL = `SESSION_TTL_HOURS` (the prompt copy says "about 12 hours").
- **Rate limit:** per `ip|folder`, default 10 attempts / 300 s; the 11th is **429** even with the right
  password; success resets the bucket.
- **Finding unlisted things:** `GET /_/unlisted` (admin: `ADMIN_PASSWORD`, `folder=@admin`) lists the roots
  of unlisted subtrees. There is no sitemap and no `robots.txt` at all.

No-existence-oracle rules, header shapes, cookie details, forward-auth bypass, and why a locked folder never
shows a card picture: `references/access-and-listing.md`.

## Structural side effects

- **Gallery rule — existence is enough.** A manifest-free flat directory of images/videos can be collapsed
  into one *gallery item* (one card, slides, downloads). The presence of **any** `.library.yml` — empty,
  comment-only, or `kind: collection` — makes it an ordinary browsable **category** whose `<dirname>.md`
  becomes the intro. The content is not read for this decision. This is the only thing an explicit
  `kind: collection` ever does.
- **`kind: app` — nothing below is content.** The folder yields zero items and zero sub-folders; its files
  are served statically (realpath-contained, dotfiles 404, no directory listings) and manifests deeper
  inside are never read. See `references/apps.md`.
- **`hidden` — nothing below is read.** Not even to warn about it.

## Triage: symptom → cause

| Symptom | Most likely cause | Confirm |
|---|---|---|
| Folder vanished / 404 after adding a manifest | manifest invalid → treated as hidden: unknown or mis-cased key, mis-cased enum, unquoted number, `password` without `visibility: protected` (or vice versa), `app:` without `kind: app` (or vice versa), malformed `preview`/`app.entry` path, duplicate key | boot/rescan log: `"<path>: invalid .library.yml — folder treated as hidden: …"` |
| Sub-folder still locked despite `visibility: public` | widening — ignored | `<details>` warning on the folder page / log `would widen inherited 'protected' — ignored` |
| Sub-folder still missing from its parent despite `listing: listed` | widening — ignored; it *is* visible inside the unlisted parent's own page | same warning, `listing` flavour |
| Correct password rejected | rate-limited (429, wait out the window); typed the **parent's** key at a **child** guard's prompt; degraded boot (scan returned nothing → old catalog kept, secrets empty) | status code; log `boot: … keeping previous catalog` |
| Card lost its picture | `preview:` points at a missing file / directory / non image-video-PDF → warning, falls back to the icon then glyph; folder is locked (never shows one); PDF previews are always a glyph in the container (no rasteriser); `None` ≠ `none` | log `preview '<rel>' was not found — ignored` etc. |
| App URL answers 500 | `app.entry` missing on disk, or inside a dot-directory, or the trusted build failed | log `app.entry '<x>' not found` / `app build failed` |
| App served without its bundle | folder not in `TRUSTED_APPS` (exact catalog path — on-disk spelling, NFC, case; not the slug) | log `app build ignored: folder is not in TRUSTED_APPS` |
| Server exits 1 at boot / `POST /_/rescan` → 500 `rescan-failed` | some folder or file path contains `password` (any case) — the catalog serialiser refuses (open bug) | log `refusing to serialize catalog: key '…' looks like a password` |
| Change not visible | no rescan yet — or the file is named `.library.yaml` (silently ignored, not invalid) | rescan (see *Rules of engagement*); `ls -a` the folder |
| Two headings on the folder page | manifest `title` differs from the intro's `# H1` — both render, on purpose | make them equal or drop one |

Complete failure table with exact warning strings: `references/failure-modes.md`.

## Recipes

Complete files live in `examples/` (index in `examples/README.md`). The shapes:

```yaml
# examples/protected.yml — protected, listed with a lock (quote the password if numeric or it contains " #" or ": ")
visibility: protected
password: "throwaway-unique-42"
```
```yaml
# examples/protected-unlisted.yml — link-only AND password-gated
visibility: protected
password: "another-throwaway-9"
listing: unlisted
```
```yaml
# examples/hidden.yml — nothing else in the file matters
visibility: hidden
```
```yaml
# examples/unlisted.yml — link-only, public
listing: unlisted
```
```yaml
# examples/rekeyed-child.yml — child of a protected parent (parent key still opens it; this key opens only this subtree)
visibility: protected
password: "child-only-key-77"
```
```yaml
# examples/protected-root.yml — whole library behind one password (file goes in the library root)
visibility: protected
password: "root-key-1"
```
```yaml
# examples/app-with-build.yml — static app (bundled only if the folder path is in TRUSTED_APPS); app-entry-only.yml drops `build`
kind: app
title: Counter
app:
  entry: app/index.html
  build: app/src/main.ts
```
```yaml
# examples/preview-file.yml / preview-none.yml — card picture from a file inside this folder, or force the glyph
preview: art/hero.png
# preview: none
```

Things that look like recipes but **do not work** (`examples/does-not-work.yml`): a `public` child under a
`protected` parent; a `listed` child under an `unlisted` parent; `kind: collection` as a way to change
anything other than the gallery rule; `title:` on a hidden folder (never shown).

## Validate a draft

No script ships with the server, but the loader is importable. Save the draft as `.library.yml` in a
**scratch directory** (never a real-library path) and run, from `~/Projects/ai-library-server`:

```sh
MANIFEST_DIR=/path/to/scratch-dir bun -e 'import { loadManifest } from "./src/scan/manifest.ts"; const r = await loadManifest(process.env.MANIFEST_DIR); console.log(JSON.stringify(r.status === "valid" ? { ...r, password: r.password === null ? null : "<set>" } : r, null, 2))'
```

`status: 'valid'` prints the `declared` keys; `status: 'invalid'` prints the exact error strings listed in
`references/failure-modes.md`. This checks the file alone — inheritance (widening) is decided at scan time
against the ancestors, so still read them.

Twenty-five verified gotchas beyond the ones above — the `@admin` folder-name collision, the `app.entry`
symlink gap, `.LIBRARY.YML` on case-insensitive volumes, `TRUSTED_APPS` matching the catalog path not the
slug, the root `title` renaming crumbs but not the header brand — live in `references/failure-modes.md`.
